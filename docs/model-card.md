# Worldline model card

Version 0.1.0. Original experimental models, trained locally from scratch on original synthetic fields. Published with the complete architecture, dataset generator and small training recipe. License: Apache-2.0.

## Purpose and output

The spatial model samples a stochastic 64 × 64 height field and vegetation-density field, conditioned on one of three classes: alpine, desert or alien. It does not generate arbitrary objects, interiors, cities, people, textures, speech or video. A separate browser renderer displays the sampled field as a 3D landscape.

The dynamics model takes three fields (water, vegetation, heat) and rain/heating controls, then predicts their next values. It is a learned approximation to the project's synthetic reaction/diffusion teacher. It is not a climate, hydrology, fire, ecology or engineering simulator suitable for real-world decisions.

## Architecture

The flow model interpolates Gaussian noise and clean fields and learns the corresponding velocity using mean squared error. A small U-Net has time and biome conditioning. Sampling uses Heun integration. Exact parameter count, selected EMA/raw checkpoint, steps, seed, data sizes and losses are recorded in `checkpoints/training-metrics.json` and checkpoint metadata.

The ecological model is a residual convolutional network with explicit control channels. A bounded numerical update keeps outputs inside the field representation. Bounded outputs are a programmed guarantee, not evidence that learned predictions are physically correct. The analytic teacher is used in training and evaluation, not in the live inference endpoint.

## Data and provenance

Training examples are generated by `worldline/data.py`, written for this project. Its terrain functions encode a narrow synthetic domain. The generator learns that distribution rather than learning the real world. The same applies to the ecological teacher. No external training videos, photographs, game assets or generative-model outputs are used.

Training and validation use different generator seeds. The training script records the distinction between validation for checkpoint choice and any final test split. The small number of sampled fields used for distribution summaries is diagnostic, not sufficient for broad distributional equivalence. Training examples are inexpensive to regenerate and are not stored as a large redistributed dataset.

## Reproducibility and privacy

Sampling initializes noise from a local CPU random generator. Identical settings in the same numerical environment should reproduce initial fields; cross-device/kernel/version bitwise equality is not promised. Saved snapshots restore the serialized fields directly and do not depend on regenerating them.

The app makes no external inference request. Initial package installation needs internet access. World files and user prompts remain in the local database unless the user exports/shares them. Model training uses synthetic data and does not ingest personal files.

Checkpoint loading uses PyTorch's `weights_only=True`. Only load checkpoints you trust; this release is not a general checkpoint-upload service. The server binds to localhost, rejects foreign origins and limits actual request body size. Public hosting and multi-user isolation have not been implemented.

## Validation limits

Unit/integration tests verify state persistence, local edit boundaries, branching, restores, request validation and related software behavior. These tests may inject simple model doubles when isolating API behavior. Such tests are not evidence of neural generation quality.

Training and benchmark measurements use the actual learned checkpoints for field generation and transition prediction. Baselines include untrained prediction, unchanged state and action-control ablations where recorded. Read exact split, sample count, hardware, tensor size and timing scope in the result files.

No external frontier model has been run head-to-head. No claim is made of photorealistic neural video, general physics, broad language understanding, three scientific breakthroughs, or parity with Genie 3. High renderer FPS and exact database restoration cannot substitute for those tests.

## Known limitations

- A finite terrain patch with only three learned terrain categories.
- A small keyword parser ignores unsupported prompt details.
- The renderer adds programmed foliage, water, sky, lighting and material detail.
- Camera motion is rendered from explicit geometry, not learned from action-labelled video.
- Local brushes are direct state edits, not neural text-based editing.
- Ecology is trained on synthetic dynamics and can accumulate errors over long rollouts or unusual states.
- Saving every revision grows disk usage; automatic retention and large-world streaming are future work.
- Numerical behavior and speed vary by device and installed libraries.
- There has been no external usability study, blinded graphics assessment or scientific novelty validation.
