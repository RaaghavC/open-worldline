# ABot-World-0-5B-LF: bounded local feasibility review

Date: September 7, 2026. Status: source, license, configuration and tensor-header inspection only. No ABot weights were downloaded, no dependency was installed, and no model was imported, run or trained for this review. This is an optional external baseline. It does not replace the original action-adapter work or resolve the failed native Wan clip's visual quality.

ABot is a plausible **separate 512×288 causal camera-control port**, provided that CPU equation tests and a guarded real forward pass. Its published executable is CUDA-specific and will not run unchanged on this Mac. Its public action interface cannot express Atrium's door-interaction pulse. The released 1280×704 setting is too close to the Mac's existing memory limits to admit from parameter counts alone.

## Actions and Atrium alignment

The exact released key order is `W,A,S,D,I,J,K,L`. The UI labels WASD as movement and IJKL as view direction, with opposing pairs W/S, A/D, I/K and J/L. It does not specify a distance or angle per key press. Thus treating a J key as an exact `pi/24` left turn would be an unverified calibration, even though its intended direction matches Atrium's yaw command. Sources: [keyboard](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/web_client/keyboard.py), [movement HUD](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/web_client/key_hud_wasd.html), [view HUD](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/web_client/key_hud_ijkl.html).

`set_act` expands one `[1,8]` binary key vector into a BF16 spatial control tensor `[1,32,F,H_rgb,W_rgb]`. Each key occupies four consecutive channels through `repeat_interleave(4,dim=1)`. The key vector is constant across the block's latent frames and all pixels. It is not our `[1,16,6]` tensor, and those four channels must not silently be reinterpreted as four independently varying commands. A pixel unshuffle by 16, then a stride-2 2×2 convolution and two 3×3 residual convolutions, produces `[B,3072,F,H_rgb/32,W_rgb/32]` which is added to the image patch embeddings. Sources: [action construction and streaming](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/pipeline/causal_inference.py), [SimpleAdapter](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/wan/modules/model.py).

Atrium stores right/up/forward meters, left-yaw/up-pitch radians and an interaction pulse for each outgoing RGB transition. Current captures use yaw and a remote door toggle, with no translations. ABot has no interaction channel and no supported direct mapping for vertical translation. Mapping yaw sign to J/L can support a declared categorical camera experiment; it loses the requested angular magnitude. Mapping both wait and interact to all-zero keys would make the two requested door actions identical model inputs, so it cannot test learned door control.

The CLI samples an action JSON once per block: `floor(block_index * action_fps * frames_per_block / video_fps)`, then holds that action. Its default action JSON is 16 Hz, whereas the retained UI/CLI video rate is 12 FPS. These are sampling/display conventions, not calibrated physics. The first streaming block displays 9 frames while later blocks display 12, so a per-transition comparison must explicitly retain the chosen command and output timestamps rather than assume the original 16 Atrium transitions align with two released blocks. [CLI source](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/scripts/inference.py).

The existing canonical first Atrium RGB is suitable for a same-input camera test. The raw open/closed first images differ at 18 channel values by one byte; any shared canonical observation remains an explicit derived-input choice. No future door state, teacher pose, depth or generated multi-view reference should be inserted into the conditioning for such a test.

## Core overlap and changes that a port must preserve

All **825 native Wan2.2 core tensor names and shapes match** the ABot header; none is missing. ABot adds six action-adapter tensors with **270,541,824 parameters**. Total: **831 tensors and 5,270,329,536 BF16 parameters**. The main convolution is `[3072,8192,2,2]`; both residual weights are `[3072,3072,3,3]`, with three 3072-element biases. The header comparison does not compare learned values. ABot's distilled core weights must be loaded as their own external checkpoint.

The shared dimensions are 48 latent channels, patch `(1,2,2)`, width 3072, FFN 14336, 30 transformer blocks, 24 attention heads of width 128, and text width 4096. This makes the existing safe streamed tensor-loader design, real-valued RoPE primitives, explicit linear dtypes and small equation fixtures useful starting points. The existing native manifest correctly rejects the six extra tensors and must not be weakened in place. A separate 831-key checkpoint manifest and loader identity are required.

The ABot YAML overrides the checkpoint config's `model_type: ti2v` to **`ci2v`**. Its execution additionally requires block-causal attention, mutable per-layer KV caches, cross-attention caches, clean-context cache updates, reference-token handling and relative RoPE. Relative RoPE retains unrotated keys, re-rotates the visible local window, and clamps temporal indices to `[0,20]`. Using our noncausal five-latent-frame native forward with these weights would change the model's equations and temporal context. [Causal model](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/wan/modules/causal_model.py), [released config](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/configs/long_forcing_dmd.yaml).

The released web pipeline always prepares five 512×512 reference slots. Missing references produce `[1,5,48,1,32,32]` zero latents and a zero slot mask. The mask zeroes initial reference embeddings, but the 1,280 reference tokens remain in the transformer and cache. Attention then processes those tokens through biased learned layers. Removing them or substituting `ref_latents=None` is not established as equivalent. A custom-input reproduction should retain this zero-reference behavior and disclose it, without loading the bundled demo references whose image provenance is incomplete.

## Denoising and output schedule

The released YAML uses four indices `[1000,750,500,250]`, warped through its shift-5, 1,000-step flow schedule. Mathematically these correspond to approximately `[1000,937.5,833.3333,625]` after warping; an implementation must retain the actual source's float32 timestep values rather than substitute these rounded labels. Each pass converts predicted flow into `x0 = x_t - sigma_t * flow` and, except after the last, mixes that prediction with **fresh random noise** at the next sigma. A fifth model call at timestep zero commits the clean generated chunk to the cache. This is four denoising calls plus one cache call, without native UniPC50 or CFG5.

The normal streaming chunk is `[B,3,48,H_lat,W_lat]`. In the first chunk the first latent is clamped to the encoded observation and its timestep set to zero at every denoising pass and cache update. Three latent frames decode to 9 first-chunk RGB frames after causal startup trimming; the retained decoder state yields 12 RGB frames for each later three-latent chunk. Two chunks therefore produce 21 RGB frames. Producing exactly 17 via cropping would be a declared evaluation crop, not the original two-chunk length.

A repeatable action comparison must save the starting noise and all three intermediate re-noising tensors for every chunk, plus reset both transformer and decoder caches. Sharing only the initial seed without documenting draw order is insufficient. Source: [streaming implementation](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/pipeline/causal_inference.py), [flow scheduler](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/utils/scheduler.py).

## CUDA requirements and what can be ported

The current source has a PyTorch SDPA helper, but that does not make the executable portable:

- `attention.py` unconditionally imports `sla_attn` and `sla_kernel`; these import Triton. `CausalWanCrossAttention` directly calls `flash_attention`, whose first checks require a CUDA tensor. Its self-attention can use the generic helper. The helper's SDPA fallback ignores variable-length masks and window arguments; any replacement needs the actual cache/mask equations, not just a backend-name change.
- `utils/memory.py` evaluates `torch.cuda.current_device()` at import. The web loader chooses `torch.device('cuda')`, installs Triton normalization and RoPE replacements unconditionally, then optionally installs FP8 GEMM quantization. The released YAML enables FP8 per-token quantization, which uses separately installed LightX2V kernels.
- The non-cache training branch compiles FlexAttention. A dedicated inference-only port can avoid that training branch and its compiler dependency, while preserving the cache inference equations. No training-port claim follows.
- Relative RoPE uses complex tensors; the other RoPE path uses float64/complex128. Flow-to-x0 conversion explicitly moves float64 operands onto the model device. As in our native port, real-valued rotary arithmetic and a separate CPU float64 scheduler step would need equation checks for these exact ABot paths.
- Streaming generation and decoding call `torch.cuda.synchronize()`. The VAE wrapper uses CUDA autocast. Default model loading can hold full CPU state alongside constructed parameters; cached text and a separate pinned streaming loader are preferable on 24 GB unified memory.

The plain convolution, normalization, linear, GRU-free action adapter and SDPA equations can be expressed in PyTorch without custom CUDA kernels. This is a feasibility inference from source, not a completed MPS port. We must preserve the CUDA implementation as an external reference and validate a new explicit path, without global method patches or changes to measured native modules. Sources: [attention](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/wan/modules/attention.py), [loader](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/web_client/pipeline_loader.py), [memory utility](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/utils/memory.py).

## Parameter and cache storage

These values are source/header arithmetic, retained in `arithmetic.json`. They are not peak-memory measurements. BF16 student parameter storage is **9.816754 GiB**. Applying the same 68,573,376-parameter FP32 exception list used by our native port would make it **9.944482 GiB** before any runtime buffer; the changed precision policy would need independent checking.

Per-layer video cache has two `[B,21*frame_tokens+reference_tokens,24,128]` tensors. There are 30 layers. Text cache has two `[B,512,24,128]` tensors in every layer.

| B=1, BF16 caches | Released 1280×704 | Proposed 512×288 |
|---|---:|---:|
| Image tokens per latent frame | 880 | 144 |
| Query tokens per three-frame chunk | 2,640 | 432 |
| 21-frame video KV | 6.344 GiB | 1.038 GiB |
| Text KV | 0.176 GiB | 0.176 GiB |
| Five 512×512 reference slots, extra KV | 0.439 GiB | 0.439 GiB |
| Weights with proposed FP32 exceptions plus all these caches | **16.904 GiB** | **11.598 GiB** |
| One materialized action map, excluding its clones/unshuffle | 165 MiB | 27 MiB |

At 1280×704, one explicitly materialized BF16 attention-score matrix for three query frames against 21 cached frames would itself occupy about **2.181 GiB**, before references, softmax storage or other activations. At 512×288 it would be about **59.8 MiB**. A fused implementation can avoid that full score tensor, but the actual MPS path has not been measured. The existing Mac's recommended MPS allocation was 17.760 GiB and the parent guard is 18 GiB with a 2 GiB available-RAM floor. A 16.904 GiB static subtotal is not sufficient headroom to admit the full published resolution. The lower resolution leaves a useful margin for a guarded pilot but still does not prove it will fit.

The author FAQ recommends at least **64 GB system RAM**, reports an RTX4090 test, and calls RTX3090 feasibility an expectation rather than a completed test. The repository targets Linux/CUDA. Its 19 GB, 16 FPS and 1.2-second statements refer to the authors' NVIDIA configuration, including its optimized path. They are not Mac measurements. The pinned HF card and later source FAQ name different CUDA versions, so reproductions should bind the exact code/environment rather than combine those descriptions. [FAQ](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/FAQ.md).

## Tiny decoder provenance and behavior

ABot vendors `wan/modules/taehv.py`, derived from [Ollin Boer Bohan's TAEHV](https://github.com/madebyollin/taehv). This audit retained the upstream pre-cutoff commit [`011dfc2112197741c540e0bdd5b7b67bcc930771`](https://github.com/madebyollin/taehv/tree/011dfc2112197741c540e0bdd5b7b67bcc930771), August 31, 2026. Its exact MIT license and README are retained under `taehv-upstream/`; the MIT notice names Ollin Boer Bohan, 2025. The upstream `taew2_2.pth` file metadata reports the same 22,884,021-byte size, but matching size and name alone do not verify the ABot copy's bytes. This review did not download either payload.

The `taew2_2` filename selects 48 latent channels and a 2× pixel-shuffle layout. Its decoder uses 2D convolutions, ReLU, nearest-neighbor spatial upsampling, channel-to-time growth and `MemBlock` features retained from preceding frames. The three decoder width stages are 256, 128 and 64, with a final 64-channel stage. Direct constructor arithmetic gives **9,923,532 decoder parameters** and **1,494,576 encoder parameters**, 11,418,108 total. The checkpoint tensor dtype was not inspected. FP32 decoder parameters alone would occupy about 37.9 MiB; activation and retained-frame memory are additional.

The native 48-channel normalized diffusion latent goes directly into TAEHV. Its output is `[B,T,3,H,W]` in `[0,1]`; the ABot wrapper maps that to `[-1,1]` for its video writer. Do not apply the full VAE's inverse mean/std a second time. Streaming state must be cleared per session. Three initial decoded frames are trimmed only at startup, yielding the 9/12-frame chunk behavior. The wrapper defines an optional first-frame warmup method, but the inspected web start path does not call it; inserting it would change decoder state and alignment.

The tiny decoder has no inherent Triton/CUDA operators in its convolution code. Its ABot wrapper adds CUDA-autocast assumptions that a portable wrapper would need to remove explicitly. It is a lower-cost approximate decoder, not an equivalent replacement for the full Wan decoder. The upstream author states that its quality is below the full VAE. A later test should decode identical saved normalized latents through both, retain both outputs, and separately check real RGB reconstruction. A fast decoder cannot establish action learning or persistent geometry. Sources: [ABot tiny VAE](https://github.com/amap-cvlab/ABot-World/blob/fdc0d63d7da6ee8e304816733921ccb606dc75e9/wan/modules/taehv.py), [upstream license](https://github.com/madebyollin/taehv/blob/011dfc2112197741c540e0bdd5b7b67bcc930771/LICENSE), [upstream README](https://github.com/madebyollin/taehv/blob/011dfc2112197741c540e0bdd5b7b67bcc930771/README.md).

ABot's code and HF model repository declare Apache-2.0, with Wan and AngelSlim attributions. Its third-party notices link TAEHV and Helios but omit their license labels. Any later source bundle should retain the upstream MIT license for TAEHV in addition to ABot/Wan notices; it should not describe those external files or weights as original Worldline research. Demo-image notices explicitly leave separate asset provenance to the redistributor, so this route should use only our original Atrium inputs. These are the inspected source declarations, not a legal opinion. ## Smallest useful follow-up, if separately admitted

1. Keep current native CPU/MPS and real-VAE diagnostics as their own experiments. Do not treat ABot as evidence that the failed native clip or our untrained action adapter is corrected.
2. Implement an external-baseline package with an explicit causal inference path and exact 831-key shape manifest. CPU fixtures should cover action repeat order, pixel unshuffle, nonzero-head equations, per-frame timestep zero for the observed latent, local-cache append/overwrite/eviction, raw-key relative RoPE and five zero-reference slots. Compare one versus two sequential chunks and independent reset sessions. A stand-in fixture establishes implementation behavior only.
3. Only after those checks, consider downloading the new pinned student and tiny decoder. Use genuine cached text with an explicit custom prompt or a separately encoded exact prefixed prompt. Encode the observed original image separately with the already pinned full VAE. The student process must not retain UMT5 or the full VAE.
4. Begin with one guarded 512×288, B=1 three-latent chunk, measuring parameter load, all five calls and actual cache/allocator peaks. Keep the existing 18 GiB/2 GiB guards and a fresh output directory. Record the reduced resolution and any precision changes. Do not extrapolate FPS from the native noncausal pair.
5. If it fits and is visually coherent, compare all-zero keys with J and L in separate reset sessions using the same observation, prompt and all noise tensors. Retain every frame and label categorical camera response. This cannot produce an Atrium door-control score or demonstrate memory of an invisible door. The original 947,712-parameter action adapter and its training gate remain separate.

No ABot local inference, camera responsiveness, image quality, MPS speed, persistent-memory improvement or training reproducibility has been demonstrated by this audit.
