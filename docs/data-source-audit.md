# Higher-resolution world-model data audit

Checked 2026-09-07. Primary publisher sources and small metadata were inspected. No dataset images, meshes, model weights, gated resources, or large archives were downloaded; no terms were accepted through an account or click-through gate. One 2.7 MB Objaverse annotation shard was read. This source audit preceded the local capture. Its proposed sizes below are historical plans. The subsequently completed capture contains 66 observations and 65 transitions per branch, with no camera translation. See [Atrium validation](../experiments/atrium_data/VALIDATION.md) for actual results. Statements below distinguish documented licenses from unresolved provenance.

## Decision

Use original procedural Blender scenes for the next 512×288 RGB/depth/camera/action pilot. Blender 5.1.2 was verified on the development Mac, with enough disk space for the proposed pilot. This route requires no outside asset download or cloud account. A timed sample is still required before estimating rendering throughput or training capacity.

The strongest external appearance/depth source here is Hypersim, but it supplies views of static scenes. Objaverse can supply selected objects after per-object license review. ReplicaCAD has useful interactive geometry but conflicting publisher license statements. Kubric MOVi-F has accessible high-resolution video/depth/poses, but this audit did not find an explicit rendered-data license in its source or public metadata. Neither unresolved route should be labeled cleared for unrestricted redistribution.

## Original Blender and CC0 route

[Blender's official licensing page](https://www.blender.org/about/license/) separates software from artwork, including images, movies, `.blend` files and other written data. It says published scripts using its Python API need GPL-compliant licensing. The project has therefore isolated the Atrium renderer under GPL-3.0-or-later and its original data under CC0-1.0. This does not assign third-party assets or other project components to CC0.

The separate [renderer license](../experiments/atrium_data/LICENSE) and [data license](../experiments/atrium_data/DATA-LICENSE) state their exact scope. Each has an applicability notice followed by the complete, unchanged official text from [GNU GPL v3](https://www.gnu.org/licenses/gpl-3.0.txt) or [CC0 legal code](https://creativecommons.org/publicdomain/zero/1.0/legalcode.txt). Full-file SHA-256 values: LICENSE `9cf8f3310dcd6f215361d2ad97ea16524aef693cf1173148606b01231db83f3e`; DATA-LICENSE `45c10acc31a53dd6f039c0006026bbb53d084d1623312413908622f309d79f9d`.

[BlenderProc](https://github.com/DLR-RM/BlenderProc) is a useful reference for RGB, depth, camera and segmentation capture. Its [license](https://github.com/DLR-RM/BlenderProc/blob/main/LICENSE) is GPL-3.0. Its inspected [installer](https://github.com/DLR-RM/BlenderProc/blob/main/blenderproc/python/utility/InstallUtility.py) defaults to Blender 4.2.1. Compatibility with installed 5.1.2 was not tested. Direct use of the installed Blender avoids an unnecessary installation for this pilot.

[Poly Haven's asset license](https://polyhaven.com/license) covers its HDRIs, textures and models under CC0, with original staff/artist provenance stated. It excludes website text, example renders, logos and user images. Website scraping is restricted. The current [API terms](https://github.com/Poly-Haven/Public-API/blob/master/ToS.md) permit free commercial use, require an identifying request header and visible credit when surfacing content through the live API. Older noncommercial API descriptions are superseded by the current [July 18, 2026 announcement](https://polyhaven.com/our-api). No live asset API was used or assets downloaded here. The original-material pilot avoids this dependency entirely.

## Hypersim

The [official release](https://github.com/apple/ml-hypersim) provides 74,619 images across 461 scenes, roughly 1.9 TB in per-scene archives, under CC BY-SA 3.0. It includes linear HDR RGB, depth, geometry/material channels and camera poses. Lossy preview images are discouraged for training. Original Evermotion meshes and V-Ray rendering software require separate acquisition. The [toolkit license](https://github.com/apple/ml-hypersim/blob/main/LICENSE.txt) is Apple's custom grant covering use, modification and redistribution with notices, not MIT.

The [official selective-download documentation](https://github.com/apple/ml-hypersim/blob/main/contrib/99991/README.md) names exact HDF5 members for camera positions/orientations, RGB and depth. A header-only request to [scene ai_001_001](https://docs-assets.developer.apple.com/ml-research/datasets/hypersim/v1/scenes/ai_001_001.zip) returned HTTP 200, byte-range support, and **2,249,481,604 bytes**. No archive was downloaded. A selective loader can therefore be evaluated without the full 1.9 TB release; its actual extraction has not been tested here.

Camera orientation maps camera coordinates to world coordinates; convert scene asset units using `meters_per_asset_unit`. `depth_meters` is ray distance to the camera center, not camera-plane z-depth. Adjacent poses provide relative SE(3) conditioning, not actuator labels. Use the supplied [scene split metadata](https://github.com/apple/ml-hypersim/blob/main/evermotion_dataset/analysis/metadata_images_split_scene_v1.csv). Keep all views of a scene in the same split. This is useful for visual/geometric learning; it cannot measure whether an action causes a door to stay open.

## Objaverse and original renders

The [official dataset card](https://huggingface.co/datasets/allenai/objaverse) describes 800K+ objects and 8.9 TB of files. The database license is ODC-By 1.0; individual object licenses include CC BY, CC BY-SA, CC BY-NC, CC BY-NC-SA and approximately 3.5K CC0 objects. The [official Python implementation](https://github.com/allenai/objaverse-xl/blob/main/objaverse/__init__.py) loads per-object annotations; its [code license](https://github.com/allenai/objaverse-xl/blob/main/LICENSE) is Apache-2.0.

Concrete bounded check: publisher metadata [000-159.json.gz](https://huggingface.co/datasets/allenai/objaverse/resolve/21e4e142159e2153706c23a3a02e55cec5591cea/metadata/000-159.json.gz) is **2,723,309 bytes**, SHA-256 `f32c359612f640343302334334491f66c5a1b2901aae3733c1dec0f97cf83706`, and contains 3,759 records. It includes `ab0d773057534cbd98d5238f9985db1b` (Horseshoe), publisher user `WirtualneMuzeaMalopolski`, license field `cc0`. No mesh was downloaded; creator/source provenance still needs verification before inclusion. A metadata label alone is not an audit of every embedded texture or recognizable design.

There are no native paired RGB/depth/action trajectories in this object collection. Render those ourselves, logging selected object IDs, creators, license URLs, hashes and modifications. Separate train/validation/test by source object, geometry family and generated scene seed; remove duplicate meshes across IDs before making unseen-object claims. Original shapes remain the smallest dependency-free start.

## Alternative 1: Kubric MOVi-F

The [official generator](https://github.com/google-research/kubric/blob/main/challenges/movi/movi_f.py) produces 24-frame, 12 FPS, 512×512 clips with moving cameras, settled objects and tossed objects. It provides RGB, ray-distance depth, flow, segmentation, camera poses and object/collision metadata. Camera motion is a sampled straight line aimed at the origin. Tossed objects receive sampled initial velocities. These are passive simulated trajectories, not recorded agent actions. The camera documentation's stale “static” sentence conflicts with the generator description; use actual per-frame poses.

Verified public [dataset_info.json](https://storage.googleapis.com/kubric-public/tfds/movi_f/512x512/1.0.0/dataset_info.json), 23,112 bytes, reports 5,737 training clips in 1,024 shards and 147 validation clips in 128 shards. Encoded split bytes total **591,980,905,818**. The [validation object listing](https://storage.googleapis.com/storage/v1/b/kubric-public/o?prefix=tfds%2Fmovi_f%2F512x512%2F1.0.0%2Fmovi_f-validation&maxResults=1000&fields=nextPageToken,items(name,size)) identifies a smallest shard of **71,755,638 bytes**, `movi_f-validation.tfrecord-00118-of-00128`. Only metadata was fetched.

The [repository](https://github.com/google-research/kubric) is Apache-2.0. Neither the inspected generator nor `dataset_info.json` declares a separate rendered-data license (`redistributionInfo` absent). Do not translate the code license into a dataset license. Existing splits randomly assign complete scenes, not necessarily distinct source assets; reserve an untouched test scene set and group by asset IDs for unseen-object claims. Its two-second clips are also too short to establish minute-scale state retention.

## Alternative 2: ReplicaCAD

The [official project page](https://aihabitat.org/datasets/replica_cad/) describes 84 released apartment rearrangements, 90+ object assets with collision/physical properties, and articulated furniture/doors. Interactive and baked-lighting versions serve different purposes; much of the baked furniture is static. The package supplies scene geometry/configuration, not ready-made action-conditioned video. New controlled renderings would be needed.

Critical license conflict: the official page and [official HF card](https://huggingface.co/datasets/ai-habitat/ReplicaCAD_dataset) declare CC BY 4.0. The actual [LICENSE.txt at revision 3e8c7fe5759f64bfcbc3882f9cdf6de97f82a06d](https://huggingface.co/datasets/ai-habitat/ReplicaCAD_dataset/raw/3e8c7fe5759f64bfcbc3882f9cdf6de97f82a06d/LICENSE.txt) declares **CC BY-NC 4.0**, with an explicit noncommercial condition. The public repository is ungated, but public access does not resolve this contradiction. Exclude it from the cleared route pending publisher clarification.

The [publisher file listing](https://huggingface.co/api/datasets/ai-habitat/ReplicaCAD_dataset/tree/3e8c7fe5759f64bfcbc3882f9cdf6de97f82a06d?recursive=true&expand=false&limit=1000) returned 622 entries and **157,450,746 bytes** summed over current files. Its 7,894-byte [scene dataset configuration](https://huggingface.co/datasets/ai-habitat/ReplicaCAD_dataset/raw/3e8c7fe5759f64bfcbc3882f9cdf6de97f82a06d/replicaCAD.scene_dataset_config.json) points to stages, objects and URDFs. Habitat-Sim code is [MIT](https://github.com/facebookresearch/habitat-sim/blob/main/LICENSE), separately. Random apartment micro-variations would leak most geometry across splits; hold out macro layouts and object families. Native Habitat setup on this Mac was not tested.

## Smallest useful original pilot and validation gates

These are proposed experiment sizes, not completed capture or quality results. The implemented first capture is documented separately above.

1. Render **16 smoke-test frames** covering a camera translation, camera rotation, closed/open door, and the same camera after returning. Check RGB by eye before enlarging the batch. Record warm-up and steady render time, samples, denoiser, Blender version, resolution, seed and peak memory. Do not infer throughput from tool availability.
2. For one scene, capture two **65-frame branches for 64 transitions**: common initial view, open versus no-open action, leave the door out of view longer than model context, then return. Use identical camera/action timing apart from the intervention. A single paired scene checks the capture schema, not learning/generalization.
3. A small learning pilot is **12 independent scene designs**, 8 train/2 validation/2 untouched test, each with two 64-transition branches: **1,536 transitions and 1,560 RGB/depth observations**. Keep both branches and all camera paths from each scene in one split. This can expose a failed training pipeline; it cannot establish frontier visual quality. A later 64-scene version produces 8,192 transitions/8,320 observations.
4. Save actual `action[t]`, pre-state observation `RGB[t]`, and resulting `RGB[t+1]`, plus commanded and realized camera transforms, intrinsics, timestamps, units, door angle and object IDs. Preserve per-frame state for scoring, but do not expose hidden state/depth/renderer to a model whose claim is RGB-history-plus-action prediction. A pose-conditioned model must be labeled separately. Calibrate stored depth with a known plane and off-axis point to distinguish z-depth from ray distance; use a valid-depth mask for background.
5. Validate finite arrays and valid depth, camera rotation determinant/orthogonality, reprojection of known landmarks, matching RGB/depth/pose/action counts, deterministic repeated seeds and action alignment. Check that the open/no-open intervention changes door pixels and the return view. Also test whether shadows/reflections still reveal the supposedly hidden door. Claim identical hidden histories only when measured arrays are identical.
6. Assess held-out generated-history rollouts at 1/16/64 steps against repeat-last-frame, paired-noise branches and the existing short-context predictor. Show RGB contact sheets/video and moving-region errors beside full-frame metrics. Score the return-door region against each branch's own ground truth. Scene split size is too small for broad statistical or Genie 3 claims; report per-scene results.

Storage arithmetic at 512×288: RGB uint8 plus one float32 depth channel uses **1,032,192 bytes/frame** before headers or compression. Add uint16 object IDs for **1,327,104 bytes/frame**. Thus 16 smoke frames need about 16.5 MB RGBD; the 1,560-observation pilot needs **1,610,219,520 bytes RGBD**, or **2,070,282,240 bytes** with IDs. The 8,320-observation version needs **8,587,837,440 bytes RGBD**, or **11,041,505,280 bytes** with IDs. Add actual `.blend`, RGB/EXR encoding, manifests and derived training copies separately. Compression and render time are unmeasured. At 256×144 these uncompressed pixel totals are one quarter as large.

No static-camera benchmark, small original room set, successful capture pipeline, or rendered visual improvement establishes learned physical interaction, open-world coverage, real-time generation, Genie 3 parity, or three novel high-impact contributions.
