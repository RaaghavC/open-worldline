# Generative world models: September 8, 2026 update

Checked September 8, 2026, America/Los_Angeles. This adds selected findings to the [September 7 research review](research-2026-09-07.md).

This check covers selected world-model releases, memory failures and action conditioning. Date-targeted searches did not establish a newly dated September 8 technical model release. That is a limit of this search, not evidence that no such release exists. The additions below are older sources inspected more closely today. Search snippets, workshop schedules and crawler dates were not treated as model release dates. No models or weight files were downloaded or executed.

The recent closed-model status remains unchanged in the pages checked: World Labs describes **Atlas**, announced September 1, as entering early access with selected partners. Runway labels **GWM Worlds 2**, announced September 3, a research preview. These pages do not establish a new public-weight release. Their demonstrations remain useful comparison targets, with access and reproduction limits. [Atlas announcement](https://www.worldlabs.ai/blog/atlas), [GWM Worlds 2 announcement](https://runway.com/research/introducing-gwm-worlds-2).

**DreamX-World is a concrete open camera-control candidate, with substantial hardware requirements.** Its repository dates the 5B-Cam release to May 11 and the autoregressive 5B release and technical report to June 15. Both have linked inference code and visible weight files. The repository declares Apache 2.0; both model repositories declare MIT. These are separate declarations, and the Wan dependencies retain their own attribution and terms. [Official repository](https://github.com/AMAP-ML/DreamX-World), [5B-Cam files](https://huggingface.co/GD-ML/DreamX-World-5B-Cam/tree/main), [autoregressive 5B files](https://huggingface.co/GD-ML/DreamX-World-5B/tree/main).

The authors report these measurements on one H20. Time includes denoising and VAE decoding. Memory units below reproduce the source's notation; they have not been converted to GiB. [Published efficiency table](https://github.com/AMAP-ML/DreamX-World#computational-efficiency).

| Released variant | Video | Reported time | Reported peak memory |
| --- | --- | --- | --- |
| 5B-Cam | 5 seconds, 720p | 509 seconds | 38G |
| Autoregressive 5B | 5 seconds, 720p | 26 seconds | 40G |
| Autoregressive 5B | 60 seconds, 720p | 342 seconds | 72G |

The autoregressive model converts keyboard commands into camera trajectories and PRoPE conditioning, and reuses cached attention states. It uses Wan2.2 text and VAE components. Its documented 123 latent-frame setting produces 489 pixel frames, about 30.6 seconds at 16 fps; 123 is not the number of output images. The file listing exposes `model.safetensors`, while examples still name a `.pt` checkpoint. A [subsequent source inspection](dreamx-ar-feasibility-2026-09-08.md) confirms that the loader reads safetensors directly; the `.pt` filename is stale. It also found that incomplete checkpoint loads are not rejected by the stock entry point. [Author model card](https://huggingface.co/GD-ML/DreamX-World-5B), [actual file listing](https://huggingface.co/GD-ML/DreamX-World-5B/tree/main).

The inference instructions also default to Lab color correction at strength 1.0. Any comparison should retain raw decoded pixels and identify corrected previews separately. The camera example uses 704 by 1280, 121 frames, BF16, 50 steps and guidance 3. Those conditions differ from our retained Wan control. [Inference instructions](https://github.com/AMAP-ML/DreamX-World/blob/master/inference_README.md).

Our assessment: this is a useful future external baseline for camera response. The reported memory does not establish a runnable 24 GB Mac configuration. Camera trajectory control also does not establish learning a door interaction. The June paper's staged control, memory, causal training and distillation are existing research, so those ingredients would require attribution in a derivative implementation. [Technical report](https://arxiv.org/abs/2606.16993).

**TetherMem, August 27, studies a failure relevant to interpreting stable videos.** It routes subject and scene queries to history differently, preserving identity while reducing old-background influence. Its evaluation uses ten prompts, three seeds and primarily Wan2.1-T2V-1.3B with LongLive-RAG. The matched routing ablations preserve the generator and inference settings. A stable subject can otherwise coexist with insufficient change in the background, viewpoint or scene state. [Paper](https://arxiv.org/html/2608.26902v1).

The limitation is concrete: it tracks at most one subject and uses an offline reference rollout, then SAM 2 masks, then controlled generation. Results beyond roughly 30 seconds are qualitative. This is not demonstrated online masking on our bidirectional Wan2.2 path. The linked project page could not be inspected successfully, so an executable release and its license remain unverified here. Our inference is to score requested camera and object-state changes separately from appearance stability, including a repeated-initial-image baseline. This paper does not identify the cause of our weak command effect. [Limitations and released-artifact description](https://arxiv.org/html/2608.26902v1).

**DreamX-Phi, August 13, provides a more specific action-conditioning design than a generic action vector.** It builds on Wan2.2-TI2V-5B with separate arm-pose conditioning, gripper-state inputs, auxiliary depth supervision and object-focused learning. Its WorldArena results refer to an August 12 leaderboard snapshot. Policy evaluation covers one Adjust Bottle task; the authors explicitly say the full-system results do not isolate individual components or establish generalization to real robots. [Technical report](https://arxiv.org/html/2608.13489v1).

Its current public repository contains a description and an MIT license, while stating that inference code and weights will follow the WorldArena 2.0 IROS Challenge. It should remain a design reference, not be listed as an available reproducible model. [Release statement](https://github.com/AMAP-ML/DreamX-Phi#-release).

**EA-WM, May 7, is older but adds a useful explicit data requirement.** It maps actions and robot state through kinematics and camera projection into image-aligned action fields. A second latent stream exchanges information with the video stream; an auxiliary objective predicts VAE-encoded temporal differences to emphasize interaction changes. The reported two-stage training uses rank-32 LoRA and 32 H100 GPUs. [Method and training details](https://arxiv.org/html/2605.06192v1).

The required inputs include robot geometry, camera calibration and synchronized action-state logs. The authors identify calibration error, occlusion, noise and changes of robot embodiment as limitations. These inputs exceed our present RGB-plus-six-command interface. Our inference is that spatially explicit action supervision is a possible separate experiment, but it would require new declared inputs and training. Hidden renderer state or target geometry must not enter the current sampler under the label of action conditioning. No runnable code, weight release or implementation license was verified in this check. [Required inputs and limitations](https://arxiv.org/html/2605.06192v1).

For the current project, the useful next evidence remains the already prepared matched final-128 evaluation: identical initial image, noise and text, with only the command changed. The papers above do not justify treating a nonzero velocity difference, lower training loss or a coherent room as successful action control. A later comparison with a released camera-conditioned model should use that model's declared input semantics and report its dependency, memory and postprocessing differences explicitly.
