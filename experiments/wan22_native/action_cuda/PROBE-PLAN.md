# Separate native CUDA numerical probe

This is a preparation contract. No native CUDA adapter probe has executed. The original 947,712-parameter adapter will be tested with the literal frozen FP32 Wan2.2 CUDA foundation. The existing MPS probe is historical evidence and is not a warm start or admission for this path.

The parent accepted the following bounded numerical contract before execution. It permits neither a fixed16 study nor an action-quality claim.

1. Prepare the complete eight-window native CUDA cache for the selected `baseline` or `spatial` profile: closed/open starts 0, 8, 32 and 49. Use the verified original Atrium frames, exact destination-aligned commands, current profile preprocessing and independently encoded initial images. Canonicalize the closed start-0 first RGB to the pinned open first RGB before resizing and full-clip encoding, preserving the original files. Require completed codec, source, file/tensor and causal-prefix evidence. A high-resolution profile uses enlarged original 512×288 captures; it does not add original image detail.
2. Save the actual initial FP32 adapter tensors, positive text, two full-shape noise tensors, integer timesteps and RNG states once. Initialization seed is 20260907. The private CPU draw order is `randint(50,951)` followed by FP32 `randn` for each pair. The two paired steps use starts 0 and 8. Both branches of each step share that step's saved noise and integer time. Record the generating Torch/CPU environment. Execution verifies saved bytes; it must not regenerate Gaussian values on a different CPU architecture and treat the seed as a byte-identity guarantee.
3. Require a new parent admission with scope `two-update-numerical-feasibility-only`, exact profile, immutable prepared-plan hash, source map, input/cache/text/draw hashes, declared GPU/runtime and the retained visual diagnostic/audit evidence. The spatial visual check describes a recognizable near-static room; it does not establish action control or general model quality. The old MPS visual result remains failed.
4. Load the literal native FP32 core outside inference mode and verify all 825 original parameter values. On **both start-0 branches**, compare the unchanged native complete forward and the bridge with its exact zero-output initial adapter, before **any** optimizer update. Inputs, token times, positive text and runtime settings must match. Retain both predictions and report exact equality, maximum absolute error and `L2(bridge-native)/L2(native)`. Require **maximum absolute error ≤ 1e-6 and relative L2 ≤ 1e-6**. With a zero reference norm, relative L2 is zero only for an exactly zero difference; otherwise it is unavailable and the gate fails. Compute descriptive norms in CPU float64 after checking finite FP32 values. Any failure stops before training and retains all measured values; tolerances are never relaxed automatically.
5. Run exactly two paired optimizer updates on the fresh saved initialization. Each update performs closed then open B=1 forwards and half-loss backwards, then one AdamW step. Use future-only flow MSE over latent positions 1 through 4, with `sigma=k/1000`, noisy future `(1-sigma)*target+sigma*noise`, target velocity `noise-target`, and the independent initial latent at token time zero. No special door loss, negative prompt, teacher state, pose or depth is passed to the bridge. AdamW uses learning rate 1e-4, betas 0.9/0.999, epsilon 1e-8, weight decay 0.01, and gradient norm clipping at 1.
6. Require finite losses, all adapter gradients present and finite, a positive aggregate/output gradient, first-update GRU gradient zero, and second-update GRU gradient positive. Verify input-prefix preservation and all 825 frozen foundation values after the second update. Save immutable initial/first/second adapter and optimizer/RNG recovery bundles, branch input identities, timings, memory samples and terminal records. Preserve partial or failed evidence and the last fully valid checkpoint. Different losses on different windows/noise are not a learning-improvement metric.

The existing native resource policy remains: 900-second combined deadline, host RSS at most 48 GiB, CUDA reserved memory at most 60 GiB, at least 8 GiB available host memory and CUDA memory, exactly one visible GPU with at least 70 GiB, Torch 2.5.1, CUDA 12.4 and FlashAttention 2.7.4.post1. Parent and worker guards must remain active. Record TF32, deterministic-algorithm and attention settings without changing them between reference and bridge calls. A worker deadline is not a cloud billing limit; the parent owns the separate cloud lease and teardown.

The parent separately fixed the native CUDA codec's cross-length prefix comparison at maximum absolute and relative L2 errors of 1e-5. The probe rechecks that bound against the independent observation while preserving the full target's original bytes. Same-length future-only and repeated single-image cache checks remain exact. These codec checks do not change the stricter 1e-6 native-versus-zero-adapter gate.

The runner must default to preparing a plan. An explicit execution request requires complete current CPU reviews, current data evidence and the new admission. No data gate, CPU result or successful numerical probe automatically opens a longer training or image-quality experiment. No images are generated by this numerical trainer.
