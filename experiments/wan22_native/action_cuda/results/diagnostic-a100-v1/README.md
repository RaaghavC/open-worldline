# Fourteen-prediction diagnostic on A100

**The 16-update adapter slightly reduces two seen-example flow losses and produces a small command-dependent velocity difference. This diagnostic does not establish successful door control.** The preceding [rendered comparison](../visual-a100-v1/README.md) still shows a closed door and nearly static camera for both commands. No training update or image generation occurred in this diagnostic.

The [independent CPU audit](audit/report.json) passed on its first invocation. It checked all 14 saved predictions, four saved command differences, the exact prepared inputs and all 825 original foundation value-hash records before and after the run. Checkpoint zero matched native predictions bit-for-bit for both commands in both text contexts.

| Open example | 0.162152676773 | 0.161552561582 | 0.3700926822% |

Both examples were seen during training. The test uses the original first training noise draw and timestep, with each branch's own target-corrupted input. These four losses establish a small change on those fixed inputs; they do not isolate command response or measure held-out performance. Loss excludes the first latent frame. [Original worker metrics](metrics/worker.json), [independent reductions](audit/report.json) and the [interpretation](audit/interpretation.md) are retained.

For the separate k=999 panel, both commands receive exactly the same initial noise, independently encoded observation and text. Future targets are absent from its conditions. At checkpoint 16, the future-frame RMS command difference is 0.0003046884883 with positive text, 0.0003113022430 with negative text, and 0.001961411819 after CFG5. The guided command difference has relative L2 0.001582771553 against the closed guided velocity. Its norm is 1.287486659 times five times the positive-branch command-difference norm. The positive/negative difference cosine is 0.006401127732.

This first-step panel does not support simple CFG cancellation of the command signal as the explanation for the failed rendered response. It does not determine what happens through all 50 sampling steps. The runtime saves positive and negative velocities, not guided velocities. The audit reconstructs CFG with separate FP32 operations `negative + 5 * (positive - negative)` and checks the recorded effect metrics. It does not claim an exact comparison with a saved guided tensor.
