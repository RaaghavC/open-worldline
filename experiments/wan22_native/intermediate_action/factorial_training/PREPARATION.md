# Block 28 training on the six-arm Atrium cache

This preparation has not trained a model. It is a new 128-update study using the original 947,712-parameter action adapter after native transformer block 28. The next frozen block, original head and unpatchify remain differentiable with respect to the adapter. All 825 foundation parameters remain frozen. No video is generated by this program.

The six captured arms cross stationary, left-turn and right-turn commands with closed/no-interaction and first-frame interaction. Each pair starts from the same original image and differs only in its first interaction pulse. The camera command is 0 or ±π/120 radians per transition. These are six development clips from one room, not an independent scene split. The raw native-resolution RGB and encoded targets are unchanged.

The ordered motion pairs cycle stationary, left, right for 128 updates, giving 43, 43 and 42 paired updates. Every fourth update, starting at 1, adds the unchanged original auxiliary loss. Its 32 uses are distributed 11, 11 and 10 across the three motions. Every update calls the existing `effect.paired_update`: two half-weight future-only flow losses, optional lambda-1 CFG endpoint-difference loss, one gradient clip at 1, and one AdamW step. There are 256 main predictions, 64 auxiliary feature extractions and 128 auxiliary head predictions. Both CFG contexts train the adapter in the auxiliary loss.

All 128 noise tensors, k values and saved RNG states come byte-for-byte from the published original effect-training packet. None are regenerated. The original initial adapter and positive/negative text tensors also remain exact. A fresh optimizer uses lr 1e-4, betas 0.9/0.999, epsilon 1e-8 and weight decay 0.01. This schedule reassigns the original draws to the new camera pairs; it is not a replay of the old data order.

The actual VAE receipt binds eight encodes, 12 bit-exact prefix checks and 196 unchanged VAE values. Preparation additionally requires each raw full-target prefix to be bit-exact to the separate observation. There is no prefix repair. The earlier actual CUDA placement profile supplies 16 exact native/full/cached comparisons and four completed updates. Before this new training, two additional native-versus-zero-adapter checks must be bit-exact on the first new-data pair. No optimizer update occurs before those pass.

The previous block-29 comparison used older data. A successful new-data block-28 run would not establish that placement 28 is better than placement 29. That conclusion needs a matched new-data control. Numeric training completion would not establish door control, camera response, image quality or generalization.

## Commands

Run from the repository root. Set `PROGRAM` to this directory and use a Python environment with the pinned dependencies already installed. The files import the existing repository packages and their own uniquely named sibling modules. The old VAE/profile bare-module runners are used only by the separate `validate_prior.py` process, never imported into the new training process.

```sh
export PYTHONDONTWRITEBYTECODE=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
export PYTHONPATH=".:$PROGRAM"
python -m pytest -q "$PROGRAM/test_cpu.py"
python "$PROGRAM/training_run.py"
python "$PROGRAM/training_run.py" --prepare \
  --original-run /path/to/public/recovered/action-results/effect128-spatial-v1 \
  --cache-run /path/to/verified/recovered/action-results/factorial-native-cache-v1 \
  --profile-run /path/to/verified/recovered/action-results/intermediate-profile-spatial-v1 \
  --cpu-report "$PROGRAM/cpu-v2/report.json" --output /path/to/fresh/prepared
python "$PROGRAM/training_run.py" --preflight --prepared-directory /path/to/fresh/prepared
```

Preparation requires the exact pinned original catalog and prior actual receipts, current unchanged source files, completed CPU evidence and the original parent/worker evidence. It copies 19 input files, small prior records and 88 source files. Original recovery remains the complete source of the prior raw predictions, encoded files and 825/196 value maps. `original-inputs.json` records their public index and original file locations; operational original paths are provenance, while the new packet uses stable basenames.

Actual execution needs a separate source/input-bound admission for this scope and GPU. The CLI is explicit:

```sh
python "$PROGRAM/training_run.py" --execute \
  --prepared-directory /path/to/fresh/prepared --weights /path/to/pinned/weights \
  --expected-gpu 'EXACT GPU NAME' --admission /path/to/new-admission.json
```

The parent and worker share one 900-second deadline including preparation checks, load, training, source verification and output hashing. The existing 60 GiB CUDA reserved-memory cap, 48 GiB host RSS cap and 8 GiB available-memory floors are unchanged. A separate external lease must leave at least 900 seconds plus the required recovery reserve before dispatch. The current rental's start cutoff was missed, so this packet was not launched there.

The parent uses a bounded configuration file, supervised child, and retained failure/cleanup records. Results include all main and auxiliary predictions, 128 clipped-gradient bundles, load metadata, all 825 current-value hashes before and after training, immutable checkpoints 0/16/32/.../128 with optimizer and RNG recovery, and timing/memory records. A failed update cannot advance the last-valid checkpoint. Checkpoint recovery is retained for audit; automatic resume is not implemented. Peak training memory is recorded after its reset immediately before parity and updates; the sampled monitor also covers loading. No claim of full-run solver replay is made.

## CPU evidence and limits

`cpu-v2/report.json` records 15 passed CPU checks and unchanged sources. A tiny literal native model exercises two actual main/auxiliary updates through the frozen suffix; a separate stand-in checks the complete 128-row dispatch and output counts. Other checks reject changed command/prefix/noise/header evidence, stale admission, expired deadlines and cleanup failures. These CPU cases do not execute the full CUDA foundation or measure its 128-update time or memory.

`cpu-v1` is retained: 14 checks passed and one synthetic file-writer fixture failed because several test tensors shared storage. The corrected fixture makes independent copies before writing. Production math and inputs were not changed for that correction.
