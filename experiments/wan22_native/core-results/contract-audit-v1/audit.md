# Native Wan2.2 sample contract audit after visual failure

The completed clip failed visual inspection despite finishing all 50 sampling steps. This source and saved-tensor audit found no integer-timestep quantization, doubled solver shift, missing negative-branch image condition, or latent-normalization mismatch. These checks do not establish that the Mac numerical path matches an official CUDA run. Training remains a separate, closed runtime gate while the failed reference is investigated.

The executed clip metadata hashes are `17d52167ef71b804f4de36b9855607410ae3134bb0d4d36cdc948dd6f9bea1bc` for the parent and `521e900332fa15f4fcb36b393fefe7b73ed05eff06f05623405f9a4f73396d6d` for the core. The source reviewed is the retained `sample_clip.py` and its measured dependencies, against official Wan2.2 commit `42bf4cfaa384bc21833865abc2f9e6c0e67233dc`. No model was constructed or executed. Small CPU mask/scaling calculations and reads of saved observations, text and output latents are separate from inference.

## Differences that remain unisolated

The Mac core stores most linear/convolution weights in BF16 and explicitly retains FP32 norm weights, time modules, modulation, residual arithmetic and output head. Attention uses MPS BF16 SDPA, with real-valued RoPE and CPU double timestep math. The official route uses CUDA BF16 autocast, CUDA attention kernels and complex double RoPE, with an optional whole-model dtype conversion. Existing tiny CPU comparisons validate the declared equations and conversions, but do not compare actual full-model CUDA and MPS velocities. [Official model](https://github.com/Wan-Video/Wan2.2/blob/42bf4cfaa384bc21833865abc2f9e6c0e67233dc/wan/modules/model.py), [official setup](https://github.com/Wan-Video/Wan2.2/blob/42bf4cfaa384bc21833865abc2f9e6c0e67233dc/wan/textimage2video.py#L119).

The native VAE defaults to FP32, consistent with our codec. Its unchanged equations and exact 48-channel normalization are supported by the [official VAE source](https://github.com/Wan-Video/Wan2.2/blob/42bf4cfaa384bc21833865abc2f9e6c0e67233dc/wan/modules/vae2_2.py#L888). Allocator cleanup changes scheduling and reuse of unused buffers, not the codec equation. A complete real-video codec roundtrip still provides a stronger localization check than the existing one-image and synthetic-noise decoding measurements.

Our 512 by 288, 17-frame shape is much smaller than the native configuration's 121-frame, approximately 720p output. The native preprocessing selects an area-constrained size and crops on multiples of the VAE/patch stride. Our source image already occupies a divisible 512 by 288 grid, and no resize or crop is performed. Shape acceptance and successful token construction do not prove the model behaves well at this spatial/temporal scale. The low-resolution docstring also mentions shift 3, whereas this run used the TI2V model configuration's shift 5. This is a declared setting choice whose quality effect is unmeasured, not an identified arithmetic bug. [Native image preprocessing](https://github.com/Wan-Video/Wan2.2/blob/42bf4cfaa384bc21833865abc2f9e6c0e67233dc/wan/textimage2video.py#L457), [TI2V configuration](https://github.com/Wan-Video/Wan2.2/blob/42bf4cfaa384bc21833865abc2f9e6c0e67233dc/wan/configs/wan_ti2v_5B.py).

The current source evidence does not justify a new floating-timestep or unclamped-negative sampler. Preserve this failed clip and its declared precision/shape. The next diagnostic should isolate a still-unverified factor, such as complete codec reconstruction or a matched stronger numerical/shape reference, before interpreting adapter training as the solution. No additional run was launched by this audit.
