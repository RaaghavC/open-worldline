GitHub Linux CI at commit `b6f5841adb6afe1f040436225c4f5bf1c29bd121` passed 54 of 55 new action/data checks. The tiny codec fixture failed exact equality between its standalone initial-image latent and its full-video prefix. All 55 checks passed on the Mac. The real Mac eight-window cache also passed all 11 recorded exact causal checks.

The [original Linux failure](linux-ci-failure.log) is retained. A [separate diagnostic](../../codec_cpu_diagnostic.py) compares the outputs with oneDNN enabled and disabled, at one and two CPU threads. It records maximum errors, differing element counts, input hashes and the unchanged production source. On the Mac all four configurations were exact; oneDNN is unavailable in that Torch build. [Mac measurements](mac-diagnostic.json).

The [Linux diagnostic](linux-diagnostic.json) completed. All four thread/oneDNN configurations showed the same 134 differing values out of 192, with a maximum absolute difference of 2.086162567e-7 between standalone and full-video encoding. Same-length future perturbation and standalone A/B/A repeat stayed exactly equal in every configuration. Disabling oneDNN did not remove the cross-length difference. The precise operation causing the difference is being checked separately. No codec source, actual cache, production equality check or measured source binding was changed to make this test pass.

The separate [portable CPU fixture](../../test_codec_cpu_portable.py) retains exact tensor and byte equality for same-length future perturbation and repeat isolation. Only its fixed tiny-fixture comparison across different encoding lengths uses an absolute bound of eight FP32 epsilon values (9.536743164e-7), with no relative tolerance. It also proves that the unchanged production check rejects an epsilon-sized difference. Linux CI uses this fixture in place of only the old cross-length exact assertion. The original fixture, its failed Linux result and its successful Mac results remain retained. No model or cache rule is weakened.
